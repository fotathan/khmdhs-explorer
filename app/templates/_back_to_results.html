{# _back_to_results.html — a "back to the list" link that keeps the list. Lists and the detail pages they lead to: / (search) → /act/ /authorities → /authority/ /contractors → /contractor/ /explore (overview) → /authority/, /contractor/ Every list keeps its filters (and page, where it has one) in the address bar: the results sit inside
, so the form and the pager both push their querystring. The list page calls remember_results(path), which on load and after every swap copies window.location into sessionStorage under that path, and marks the path as the LAST list this tab visited. A detail page can be reached from more than one list (an authority from /authorities or from /explore), so back_link takes every list that leads to it, as [path, label] pairs — the first is the default — and picks, most precise first: 1. the tab's last visited list, when it is one of them; 2. document.referrer, when it IS one of them — a detail page opened in a new tab may start with empty sessionStorage (Referrer-Policy strict-origin-when-cross-origin sends the full same-origin URL); 3. any of them this tab has stored, in the order given — e.g. search → act → authority still returns to the authorities list you filtered; 4. the server-rendered `fallback` href — no script, or no list visited. The label follows the list it returns to. Only a same-origin URL on exactly one of the given paths is ever accepted. Stored per tab, never sent anywhere. Imported without context: the caller passes already-translated labels and the fallback href. #} {% macro remember_results(path) -%} {%- endmacro %} {% macro back_link(lists, fallback) -%} {{ lists[0][1] }} {%- endmacro %}
